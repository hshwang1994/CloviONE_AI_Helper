## NOW
**S16 이 W6 을 끝냈다.** 이번 회차가 답한 질문은 하나다 — **표가 비교를 할 수 있게 되어 있는가.**

표의 존재 이유는 비교인데, 열이 자기 폭과 정렬을 **숫자로** 적고 있었다. 그 숫자는 화면마다
따로 정해졌고 그래서 같은 뜻의 값이 화면마다 다른 폭과 다른 정렬로 나왔다 — 개수인데 자릿수가
세로로 안 맞는 열이 여덟이었다. 그래서 **열이 폭 대신 의미를 말하게 했다**(D-288): 타입 열넷이
폭·정렬·자릿수 고정·넘침을 준다. 여덟은 0 이 됐고, 아홉 번째가 생길 자리도 함께 닫혔다.

같은 회차가 닫은 것 다섯:

* **열을 언제 빼도 되는가** — 표는 **호출부가 준 질의 계약** 없이는 아무 열도 안 없앤다
  (D-289). 「이번 페이지의 값이 우연히 같다」로 열을 빼면 페이지를 넘길 때마다 열이 생겼다
  사라지고, 사용자는 자기가 무엇을 해서 표가 바뀌었는지 알 수 없다
* **그 자리 편집** — 상태 기계를 공통 계층 하나에 뒀다(D-290). 그중 하나는 못박았다:
  **성공은 서버가 돌려준 값으로 그린다** — 넘겨준 값이 아니라. 배선은 티켓 도메인 회차의 몫이다
* **그림** — 열둘이 각자 답하는 업무 질문을 갖는다(D-291). 「담당자별 완료 업무량」 막대 하나는
  지웠다 — 바로 아래 표가 같은 숫자를 말하고 있었고, 게다가 막대는 값이 0 인 사람을 빼고 그려
  **표와 명단이 달랐다**
* **판독값의 색** — 심각도가 없으면 Brand 잉크, 있으면 상태색이 이긴다(D-292). 그 자리를 화면이
  선언한다 — 선언이 없으면 프로브가 「DOM 의 첫 칸」을 지배값으로 읽는다
* **선택의 표현** — PLAN 이 W6 에게 닫으라고 적어 둔 충돌이다. 이 제품은 선택을 세 자리에서
  **Brand 레일**로 말하는데 검사는 면을 요구했다. `selected_state` 를 잉크 role 로 옮겼다
  (D-293) — 무채색 선택은 여전히 실패한다

🔴 **실브라우저가 시험이 못 보던 것을 잡았다.** `/work-board` 는 **아무에게도 안 열리고 있었다** —
