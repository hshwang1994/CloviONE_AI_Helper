## alembic — 이식하지 않는다 (D-189)

61 revision 을 PG 에서 재생하지 않는 이유:

| 장애물 | 수 | PG 에서 무슨 일이 |
|---|---|---|
| boolean `server_default=sa.text("0"\|"1")` | **31곳** | 타입 오류 |
| FTS5 virtual table + trigger DDL (0030 · 0050) | 2 revision | PG 에 문법 자체가 없다 |
| **`sqlite_where=` 부분 유니크 인덱스** | **3개** | **`WHERE` 가 조용히 사라져 전체 유니크가 된다** → 승인 재요청 · 프롬프트 2차 버전 · 2회 offboarding 이 막힌다 (R2) |
| `recreate="always"` | 3곳 | PG 에서도 전체 테이블 재작성 |
| 0055 의 전제 | 1 | "SQLite 는 기존 데이터를 새 FK 로 소급 검사하지 않는다"에 **의존**한다 — PG 에서는 거짓 |

→ `alembic/versions/` → `alembic/legacy_sqlite/`(비활성 보관), `0001_pg_baseline.py` 하나로 재시작.

## `VARCHAR(n)` 길이 감사 (S1 · P-04 — 완료)

**선언의 정본은 모델이다** — `app/models_registry` 의 `Base.metadata` 를 읽었다. 실데이터는
접근 가능한 최신 스냅숏(`var/web.sqlite3`, 2026-08-17, alembic `0059`)에서 쟀다.

| 항목 | 값 |
|---|---|
| 모델이 선언한 `VARCHAR(n)` 컬럼 | **410** |
| 그중 스냅숏에서 값이 하나라도 있는 컬럼 | **268** |
| 값이 전부 NULL 이라 못 잰 컬럼 | **142** (표 37개) |
| **선언 길이를 넘긴 컬럼** | **1** |

### 넘긴 것 하나 — 그리고 그건 legacy 가 아니다

| 컬럼 | 선언 | 실측 최대 | 초과 행 |
|---|---|---|---|
| **`messages.message_id`** | `VARCHAR(64)` | **77** | 3 |

값 모양은 `a-{사용자 message_id 33}-fail-{job.id 36}` 다. **지금 코드가 만든다**:
`app/jobs/handlers/chat_message.py:283` 이 `a-{33}-{36}` = **72자**,
`:285`·`:381` 이 `a-{33}-fail-{36}` = **77자** — 둘 다 64를 넘는다.
게다가 이 컬럼은 `uq_messages_conversation_message_id` 유니크 키의 일부다.

SQLite 는 길이를 무시했으므로 아무 일도 없었다. **PG 에서는 `INSERT` 가 거부된다** —
즉 Migration 뿐 아니라 **이식 직후 런타임 채팅 실패**다. 실 PG16 에 같은 값을 넣어 재현했다
(S1 실측). 대응은 S2 가 `0001_pg_baseline` 을 쓸 때 결정한다 — **길이를 넓히는 쪽이 맞다**
(id 는 절단하면 유니크 키가 깨진다).
