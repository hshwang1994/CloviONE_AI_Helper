## alembic — 이식하지 않는다 (D-189)

61 revision 을 PG 에서 재생하지 않는 이유:

| 장애물 | 수 | PG 에서 무슨 일이 |
|---|---|---|
| boolean `server_default=sa.text("0"\|"1")` | **31곳** | 타입 오류 |
| FTS5 virtual table + trigger DDL (0030 · 0050) | 2 revision | PG 에 문법 자체가 없다 |
| **`sqlite_where=` 부분 유니크 인덱스** | **3개** | **`WHERE` 가 조용히 사라져 전체 유니크가 된다** → 승인 재요청 · 프롬프트 2차 버전 · 2회 offboarding 이 막힌다 (R2) |
| `recreate="always"` | 3곳 | PG 에서도 전체 테이블 재작성 |
| 0055 의 전제 | 1 | "SQLite 는 기존 데이터를 새 FK 로 소급 검사하지 않는다"에 **의존**한다 — PG 에서는 거짓 |

→ `alembic/versions/` → `alembic/legacy_sqlite/`(비활성 보관), `0001_pg_baseline.py` 하나로 재시작.

## 완성도 — S1 이 마저 할 것

- **`VARCHAR(n)` 13개 컬럼 실데이터 길이 감사** (R7). SQLite 는 길이를 무시했고 PG 는 강제한다.
  알려진 것: `ticket_cache.title(500)` · `document_cache.original_url(1000)` · `trash_items.title(400)`
  — 나머지 10개를 열거하고 실제 최대 길이를 잰다
- 27개 `*_json` Text 컬럼 열거 (S2 의 `jsonb` 이전 대상). 단
  **`approvals.request_payload_json` 은 유니크 키의 일부**라 별도 취급이 필요하다
- PG 이식 대상 ~60 테이블과 폐기 대상(Notion 미러 3종 + `user_notion_mappings`) 확정
