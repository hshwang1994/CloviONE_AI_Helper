## 왜 이것이 보안 구멍이었나 — **이 문단이 제거의 근거다**

n8n 이 `returnAll: true` 로 Notion 작업 DB **전체**를 가져와 runner 에 넘기고, runner 는
`tickets[:800]` 을 그대로 모델 프롬프트에 실었다(`assistant.py:3156`).
**요청자는 대명사 해석(`내 티켓`)에만 쓰이고 필터로는 쓰이지 않았다.**

같은 저장소의 `app/assistant/facts.py:169-176` 은 정반대로 `viewer=user` 를 넘기며
「사용자가 화면에서 볼 수 없는 일을 답변으로 알려 주면 그것도 유출이다」라고 적어 두었다.

**즉 설계 선택이 아니라 한 경로만 이 모델을 우회하고 있던 것이다** (D-202 · D-265).
S10 이 `effective_visibility_clause` 를 AI 경로에 적용해 대체 경로를 세웠고, S11 이 옛 경로를
걷어냈다.

## 이관한 것 — 「끄고 나서 옮기지 않는다」

INVENTORY 가 적어 둔 순서를 그대로 지켰다:
**워크플로 Export 보관 → 로직 이관 → 자체 경로 검증 → n8n 정지 → 제거.**

| 무엇이 러너를 부르고 있었나 | 어디로 갔나 |

| 채팅(`chat_message` → n8n → 8789) | `app/ai/retrieval::answer()` — `/ai` 가 부르는 **같은 함수**다. 권한이 검색보다 먼저 걸린다 |

`assistant.py` 6,395줄 중 **이관 대상은 없었다**(R9 종결). 의도 분류·규칙 기반 티켓 질의·

있는 유일한 자리다 — 남은 것은 Notion API 를 직접 두드리는 코드였다. 그것은 옮길 것이 아니라
