# 최종 시각 수용 판정 기록 — 2026-10-02 (계획 8.5 · D-553, 묶음 P17V)

자동 검증(치수 · 조합 · 시각 규율 프로브, 상태별 캡처, 로컬 E2E)을 돌린 **뒤에** 최종 스크린샷을 Read 로 직접 열어 열다섯 항목으로 판정했다.
1366×768 · 1920×1080 은 전부 봤고, 1600×900 · 2560×1440 은 프로브가 걸린 칸만 봤다. 발견은 공통 부품 · 규칙에서 고치고, 고친 뒤 다시 찍은
캡처로 판정을 닫았다(화면별 CSS 패치는 없다).

| 라벨 | 내용 |

열다섯 항목: ① 첫 시선이 이상함 ② 주 동작을 찾기 어려움 ③ 입력과 단추가 어긋나 보임 ④ 라벨 시작점이 다름 ⑤ 카드가 너무 많음 ⑥ 빈 공간이 너무 큼

## 프로브(자동) — 위양성과 실제 결함을 가른 결과

첫 판정(`ux-after-measure`)의 실패는 대부분 **프로브가 2560 구간의 루트 글자 18px 를 계약값에 곱하지 않은** 위양성이었다(단추 34 → 38.25, 칸 34 →
38.25, 건수 칩 20 → 22.5 처럼 비례로 선 값을 실패로 셌다). `composition_checks.py` 는 이미 `R = rootPx / 16` 을 곱하고 있었다.

| 프로브 | 무엇이 틀렸나 | 고친 것 |
|---|---|---|
| `kit_measure` 치수 전부(2560) | 계약값(px, 루트 16)을 곱하지 않음 | `contract_for(root_px)` — 루트 비율을 곱한다(허용 오차 포함). 굵기 · 비율 · rem 계단 · 스스로 곱하는 스위치 · px 마스코트 · 둥글기는 곱하지 않는다 |
| `filter_toggle` | 34 를 숫자로 박아 둠 | 계약의 칸 높이 |
| `search_slot` | 계단(64rem 20 · 44rem 16 · 그 아래 제 줄 전체, D-530)을 몰랐다 | 필터 면 내용 폭으로 계단을 고른다 |
| `filter_composition` · `list_surface` | 작업 공간 판의 도구 줄 · 채움 표 발을 몰랐다 | 판 도구 줄 안 면 · 채움 표 발은 그 판의 고정 줄이다 |
| `first_data_visible` | 설정 줄 · 선택 카드를 폼 칸으로 안 셌다 | `.k-settingrow` · `[role=radiogroup]` 를 센다 |
| `primary_budget` | 비활성(회색) 채움 단추를 셌다 | 비활성 제외, 대화 입력 칸은 자기 몫 |
| `mascot_size` | 애니메이션 `scale` 이 걸린 테두리 상자를 쟀다 | 배치 높이(`offsetHeight`) |
| `column_balance` | 잘린 열이 이미 제 상한에 닿았는데도 옆 열의 여유를 실패로 셌다 | 더 받을 수 있는 열만 센다 |

프로브가 잡은 **실제 결함**도 있었다 — 고쳤다.

| 결함 | 원인 | 고친 것 |
|---|---|---|
| 2560 표 머리가 행 높이(55px)로 섰다 | 2200px 이상의 위아래 여백 10px 를 테마가 모든 표 칸(`root`)에 줘 머리 칸의 5를 덮었다 | 그 여백을 몸 칸(`body`)으로. 묶음 줄 · 빈 띠는 자기 여백을 지킨다 |
| 2560 빈 띠 84px | 같은 여백 | 같은 수정 |
| 2560 셀렉트 · 자유 입력 필터의 접두 들여쓰기가 자동완성과 2px 다름 | 셀렉트는 MUI 14px, 자동완성은 rem | 필터 칸 해부의 왼쪽 여백을 rem 하나로 |
| 프로젝트 · AI 연결 · 메일 설정의 첫 데이터 | 위 표 | 위 표 |

프로브 자기 시험은 `KIT_MEASURE_SELFTEST_OK`(부품 · 조합 틀린 견본 28종 전부 잡음, 맞는 견본 오탐 0)와 `tests/unit/test_ui_visual_probes.py` ·

## 받아들인 것과 열린 것

적대 데이터에서만 서는 것(받아들임 — 실제 값으로는 생기지 않는다):

- 조직 관리 「긴 이름 · 이메일」의 역할 칸 말줄임(`column_balance` 값 길이 열) — 역할은 닫힌 집합(다섯 낱말)인데 적대 데이터가 200자 낱말을 넣었다.
  칸 폭 안 말줄임 + 전체 값 툴팁이 맞는 동작이다.
- 정책 「긴 데이터」의 상태 칸 말줄임과 묶음 줄 41px(계약 36) — 적대 데이터가 상태 낱말 · 종류 이름까지 길게 바꿔 묶음 머리가 두 줄로 섰다.
- 사용 통계 「긴 데이터」의 첫 데이터 477px — 적대 데이터의 긴 기능 이름이 지표 한 줄을 두 줄로 접었다.

상태가 더 말해야 하는 것(받아들임 — 상태 면이 「지금 상태」의 자리다):

- 메일 설정 「오류」(1366 에서 첫 폼 칸 511px, 개발 PC 기준) — 실패 단계와 까닭 문장 상자가 상태 면에 선다. AI 연결 「재로그인 필요」(444px)도 같다.
- 메일 설정 「로컬 릴레이」(490px, 개발 PC 기준) — 릴레이 두 줄(구성 요소 · 바깥 전달)이 선다.
