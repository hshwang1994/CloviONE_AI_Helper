## 준비 점검 (`POST /api/admin/mail/relay/check`, 13:1x KST)

준비 15개 중 11개 통과. 막는 넷 — SPF(공개 SPF 에 도메인이 아닌 include 로 레코드 오류 + 발신 IP 없음) · DKIM(공개키 TXT 없음) ·
PTR(221.147.80.201 역방향 이름 없음) · HELO(서버 이름 `clovirassist.gooddi.lab` 은 공개 DNS 에 없음). 새 점검 줄:

| 줄 | 결과 |
|---|---|
| `egress_vs_web` | 웹 주소 `clovirassist.goodmit.co.kr` 는 221.147.80.210, 메일은 221.147.80.201 에서 나간다 — 서버 이름 · PTR 은 메일이 나가는 IP 의 이름이어야 한다 |
| `sender_alignment` | 보내는 주소 · 봉투 주소 · DKIM 서명 도메인이 모두 `goodmit.co.kr` — 정렬됨 |
| `dmarc` | 있음(`p=none`) — **새로 제안하지 않는다**(둘이면 무효), quarantine 상향 권고만 |

생성된 요청문(화면 「문제 해결과 고급」 → 「담당자에게 요청하기」에서 그대로 복사):

1. **도메인 DNS 담당자** — `[TXT] goodmit.co.kr` = `v=spf1 ip4:221.147.80.201 include:spf.protection.outlook.com include:mail.stibee.com -all`
   (깨진 `include:google-site-verification=…` 은 빼고, 그 값은 별도 TXT 로 남기라는 문장 — `6c5323bf`), `[TXT] ca1._domainkey.goodmit.co.kr` =
   DKIM 공개키, `[A] clovirassist-mail.goodmit.co.kr` = 221.147.80.201(메일 전용 이름 — 웹 이름은 다른 IP 라 쓸 수 없다, NAT 대안 문장 포함).
2. **회선 또는 클라우드 업체** — `[PTR] 221.147.80.201` = `clovirassist-mail.goodmit.co.kr`(또는 NAT 로 메일을 .210 으로 내보내고 .210 의
   PTR 을 `clovirassist.goodmit.co.kr` 로).
3. **받는 쪽 메일 관리자(Microsoft 365)** — 레코드 확인, (선택) `noreply@goodmit.co.kr` 공유 사서함 · 메일 연락처에 표시 이름
   「ClovirAssist」와 제품 표식 사진(받은 편지함 발신자 아이콘), 통과 뒤 Message-ID 로 `compauth=pass` 확인. 「스팸 필터 예외나 IP 허용
   목록은 요청하지 않습니다.」
