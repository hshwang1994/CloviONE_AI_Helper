# 제품 전체 아이디어 백로그 (2026-07-29 브레인스토밍)

> 팀 공간 근시일 계획은 `docs/NEXT_SESSION_PLAN.md`. 이 문서는 그보다 넓게, 제품 전체 관점에서
> "더 좋게 만들 것"을 모은 것이다(내 의견 포함). 아직 확정 설계 아님. 착수 시 하나를 골라 스펙으로
> 수렴한다(YAGNI: 전부 만들지 말 것, 가치 높은 소수만). 관련 [[clovirone-team-space]] [[clovirone-web-assistant]].

## 큰 그림 진단 (내 생각)
기능은 넓게 깔렸는데 "매일 여기서 하루를 시작할 이유"가 약하다. 데이터가 탭마다 흩어져 있고
(티켓/문서/게시판/채팅/사용자), AI 도우미는 아직 티켓 생성/요약에 머문다. 그래서 제품 성격을
"있으면 좋은 내부 툴"에서 "매일 쓰는 업무 허브"로 바꿀 세 축이 가장 큰 레버리지라고 본다.

### 최우선 3축 (내 추천)
1. **통합 검색 + 명령 팔레트(Ctrl+K)**: 티켓/문서/게시판/채팅/사용자를 한 곳에서 검색+점프.
   문서 캐시(그리고 성능 근본안 하면 티켓 캐시)가 로컬에 있으니 SQLite FTS로 빠르게 가능. 매일 씀.
2. **AI 도우미 심화**: "오늘 뭐 하지" 브리핑 + 문서 Q&A(로컬 문서 캐시 RAG) + 주간 다이제스트 +
   스탠드업 초안 + 미할당 티켓 트리아지 추천. 이 제품만의 차별화 지점.
3. **홈을 '오늘' 커맨드 센터로**: 오늘 마감/지연 티켓 + 나를 향한 멘션 + 안읽은 채팅 + 나에게 온 승인
   대기 + 최근 문서를 한 화면에. 하루 첫 진입 가치를 키운다.

## 영역별 아이디어

### 1. 검색 / 네비게이션
- 통합 검색 omnibox(위 1축).
- 명령 팔레트 Ctrl+K: 어디로든 점프 + 액션 실행(새 티켓, 새 문서, 채팅 시작 등).
- 최근 방문/즐겨찾기 전역화.

### 2. AI 도우미 (차별화)
- 오늘 브리핑(우선순위/마감/차단), 주간 다이제스트, 스탠드업 초안.
- 문서 Q&A(RAG): 로컬 문서 캐시 위에서 질의(러너/Claude 재사용, n8n 흐름은 무접촉).
- 미할당 티켓 트리아지 추천(담당자/난이도/우선순위).
- 회의록에서 액션아이템 자동 추출 → 티켓 초안.

### 3. 홈 / 대시보드
- '오늘' 액션 센터(위 3축).
- 나에게 온 승인 대기, 멘션, 안읽은 채팅 배지 통합.
- 팀 활동 피드(누가 무슨 티켓 끝냈는지, 새 문서 등) 요약.

### 4. 티켓 / 업무 관리
- 칸반 보드 뷰(상태별 컬럼, 드래그로 상태 변경 → Notion 반영).
- 리스트 인라인 빠른 상태/담당자 변경(상세 진입 없이).
- 티켓 의존성/차단 표시, 마감 타임라인.
- @멘션으로 티켓에 사람 끌어들이기 + 알림.
- (계획 D/E에 본문 수정/댓글 이미 있음.)

### 5. 문서
- 문서 전문 검색(FTS), "자주 보는 문서" 추천.
- 문서 → 티켓 연결(회의록 액션아이템 티켓화).
- 팔로우한 문서 변경 알림.

### 6. 팀 공간 (채팅/게임/게시판) — 계획 D/E/F 외 추가
- 채팅 스레드/답글, 고정 공지 메시지.
- 게시판 <-> 채팅 <-> 티켓 상호 링크(언급 카드).
- 게임 리더보드/전적, 정기 이벤트(점심 정하기 자동 트리거).

### 7. 알림 / 프레즌스
- 딥링크 일반화(채팅/티켓/문서/승인 목적지 매핑).
- 하루 1회 요약 알림 + 실패/장애 즉시 알림.
- (사내 SMTP 있으면 이메일 알림 검토. 없으면 인앱만.)
- 온라인/최근 접속 표시(채팅 last_seen 활용).

### 8. 관리자 / 운영 관측성
- 사용자용 '시스템 상태' 배너: AI 도우미/러너/Notion 동기화 상태를 투명하게(장애 시 "AI 응답 지연"
  안내). 지금은 실패가 조용하거나 raw error로 샌다.
- 관리자 대시보드 사용량/에러 추세(작업 큐 성공률, 동기화 지연, 로그인 실패 추이).
- 감사 로그 검색/필터 강화, 이상 로그인 알림.

### 9. 성능 / 모바일 / 접근성 / 신뢰
- 성능 근본안(문서식 캐시)을 티켓 넘어 전반 전략으로.
- 모바일 반응형 전면 점검(채팅 2단, 홈 2단, 칸반).
- 키보드/스크린리더 접근성 스윕.
- 백업/복구 리허설, 유지보수 모드 UX 다듬기.

## 부록 A. AI 도우미 = 플로팅 챗봇 (사용자 선호 방향, 2026-07-29)

사용자 아이디어: AI 도우미를 챗봇 형태로. 왼쪽 하단에 캐릭터를 두고 누르면 챗봇 패널이 뜬다.
`도우미` 탭은 아이콘을 바꾸고 거기엔 `스프린트 회의`만 남긴다(AI 도우미는 탭에서 빠져 전역 플로팅으로).

### 내 평가 (강한 찬성 + 보강 제안)
- 방향 자체는 매우 좋다. AI를 "탭 하나"에서 "모든 화면에서 부르는 전역 비서"로 승격하면 제품 성격이
  바뀐다. 핵심은 **문맥 인지(context-aware)**: 티켓 상세를 보는 중이면 "이 티켓 요약/상태 변경",
  문서를 보는 중이면 "이 문서 질문" 같은 그 화면 기준 액션을 제안. 이게 진짜 차별화다.
- **전체 화면 뷰도 유지**: 긴 대화/히스토리는 플로팅 패널이 좁다. 플로팅에서 "크게 보기"로 기존
  전체 화면(/chat)으로 확장 가능하게. 대화 히스토리의 집은 남겨둔다.
- **위치**: 채팅 위젯 관례는 오른쪽 하단이다. 왼쪽 하단도 되지만, 오른쪽에 다른 게 없다면 오른쪽을
  권장(관례 + 오른손 엄지). 결정 필요.
- **캐릭터(마스코트)**: CSP상 외부 에셋 금지 → 인라인 SVG/CSS 애니메이션으로 자급자족. 브랜드
  아이덴티티에 도움. 과하지 않게(움직임은 절제, AI스러운 과잉 연출 피함).
- **모바일**: 플로팅 버튼이 콘텐츠를 가리지 않게(스크롤 시 반투명/축소), 패널은 전체폭 시트로.
- **접근성**: 열기/닫기 포커스 트랩, Esc 닫기, aria-expanded, 키보드 단축키(예: Ctrl+/)로 열기.
- **도우미 탭**: AI가 빠지면 탭에 `스프린트 회의`만 남는다. `도우미`라는 이름이 어색할 수 있어
  `스프린트`로 개명하거나 스프린트를 `팀 공간`으로 옮기는 것도 대안(결정 필요). 아이콘 교체는 확정.

### 열린 결정(착수 때 확정)
1. 캐릭터 위치: 오른쪽 하단(권장) vs 왼쪽 하단(사용자 초안).
2. `도우미` 탭 처리: 이름 유지+아이콘만 교체 vs `스프린트`로 개명 vs 스프린트를 팀 공간으로.
3. 문맥 인지 범위: 어느 화면에서 무슨 액션을 제안할지(티켓/문서/스프린트 우선).
4. 캐릭터 디자인: 단순 아이콘 vs 표정 있는 마스코트.

### 재사용/주의
- 기존 `/chat`(대화목록 2단, 러너/n8n 연동, `app/chat`)을 플로팅 셸로 재포장 + 전체화면 확장.
- 의도 분류는 러너 `process_request()`에 있음(웹앱 아님). n8n 흐름 무접촉.
- 불변 §1(sync), §6(textContent/CSP), 폴링 모델 유지.

## 부록 B. 추가 브레인스토밍 — 사용자 + 관리자 (2026-07-29)

### 관리자 콘솔 (이전에 얕게 다룸, 여기서 보강)
- **입·퇴사 워크플로**: 입사 시 체크리스트(계정 생성, 부서/직책, Notion 연결, 환영). 퇴사 시 세션 해제
  + 비활성 + **담당 티켓 재배정**을 한 흐름으로.
- **사용자 대량 작업**: 대량 역할 변경/부서 지정, CSV 가져오기·내보내기.
- **RBAC 시각화**: 역할 x 권한 매트릭스("이 역할이 뭘 할 수 있나") — 5역할 체계 이해에 도움.
- **관리자 관점 보기(read-only impersonate)**: 지원용으로 "이 사용자가 보는 화면"을 읽기 전용으로.
  보안/감사 강하게(감사 로그 필수, 쓰기 금지).
- **승인 고도화**: 승인자 위임(휴가 대체), SLA/에스컬레이션, 승인 템플릿.
- **스케줄러 UX**: 예약 실행 캘린더 뷰, 다음 실행 미리보기, 실행 이력.
- **러너/워크플로 헬스 대시보드**: n8n/러너 실시간 상태, 마지막 성공, 에러율, 지연 → 사용자용 상태
  배너와 연동.
- **프롬프트/정책**: 버전 diff 뷰, 롤백(일부 있음), 프롬프트별 사용량 통계.
- **감사 로그**: 이상 탐지(비정상 로그인, 대량 삭제 경보), 내보내기, 저장된 필터.
- **백업**: 예약 백업 + 복구 리허설 버튼 + 무결성 검증 + 다운로드.
- **공지/브로드캐스트**: 관리자가 전체 사용자에 배너/알림 발송(점검·소식). maintenance_announcement
  알림 타입 이미 있음 → 화면화.
- **AI 사용량/쿼터**: 사용자별 AI 사용량·비용 추적, 한도(게임 AI는 §10.7 한도 개념 있음).
- **기능 플래그 UI**: 관리자에서 플래그 관리, 역할/사용자별 점진 롤아웃.
- **조직도 뷰**: 부서/직책 계층 시각화.

### 사용자 콘솔 (추가)
- **프로필 자기서비스**: 아바타 변경, 알림 환경설정, **내 다른 세션 해제**(현재 관리자만 가능),
  방해 금지(채팅 알림 일시 정지).
- **개인 생산성**: 내 업무량(WD)/부하 뷰, 내 완료 히스토리·통계.
- **저장된 뷰/필터**: 티켓 필터를 이름 붙여 저장.
- **빠른 작업 + 단축키**: 전역 Ctrl+K, "새 티켓/AI에게 묻기" 어디서나.
- **첫 로그인 투어**: 콘솔 가이드 투어.
- **내 활동 피드**: 최근 내 행동 모음.

### 외부 연동(선택)
- 사내 SMTP 있으면 이메일 알림. LINE/Slack 등 외부 채널 알림(OutboundClient allowlist 경유, 단일 관문 유지).

## 부록 C. UI 전면 재설계 (확정 방향, 2026-07-30). 아래 이전 검토를 대체함.

**상태: 향후 전면 교체 작업. 아직 구현 대상 아님(이번엔 계획 저장만 함).** 착수 시 프로젝트 전체를 먼저
분석한 뒤, 새 디자인에 필요한 만큼 프런트엔드를 처음부터 다시 만든다.

### 확정 방향 (사용자 지시 2026-07-30)
- 기존 UI를 부분 개선하거나 기존 구조에 MUI를 덧씌우는 방식은 쓰지 않는다. 전체 UI와 UX를 처음부터
  다시 설계한다.
- 기존 디자인과 프런트엔드 구조를 "유지해야 할 기준"으로 보지 않는다. 화면 구조, 메뉴 구성, 사용자 동선,
  정보 배치, 레이아웃, 폰트, 색상, 아이콘, 공통 컴포넌트, 상태 표현, 반응형 구성, 프런트엔드 코드 구조 등
  필요한 것은 모두 바꿀 수 있다(예시이며 변경 범위를 이에 한정하지 않는다).
- MUI를 새 UI 구현의 기본 프레임워크로 사용한다. 구현 단계에서 새 디자인에 필요하면 기존 컴포넌트,
  CSS, 라우팅, 상태 관리, API 연동 구조도 함께 재구성할 수 있다.
- 기존 화면은 새 디자인의 기준이 아니라 현재 기능과 데이터 흐름 파악용 참고 자료로만 쓴다.

### CSP 처리 방침 (확정)
- 내부 사용자용 시스템이므로 CSP 유지를 위한 복잡한 우회 구조를 만들지 않는다. MUI 또는 새 UI 구현을
  방해하면 CSP를 완화하거나 비활성화해도 된다. CSP 유지 자체를 UI 설계의 제약 조건으로 두지 않는다.
- 단, 이는 인증, 권한, API 접근 통제 등 다른 보안 기능을 제거하라는 뜻이 아니다(그것들은 유지한다).

### 반드시 지켜야 할 기준
- 디자인과 구현 구조는 전면 변경할 수 있지만, 현재 제공되는 실제 업무 기능과 데이터가 이유 없이
  누락되면 안 된다.
- 기존 구조를 그대로 복제하지 말고, 실제 사용 목적과 업무 흐름을 분석해 더 나은 구조로 다시 설계한다.
- 지시 항목만 기계적으로 교체하지 말고, 프로젝트 전체를 검토해 함께 바꿀 부분을 판단한다.

### 폐기된 이전 방향 (더 이상 유효하지 않음)
- 부분 리프레시(기존 커스텀 시스템 다듬기): 폐기.
- CSP 스파이크 후 리프레시 vs MUI 결정: 폐기(CSP는 완화/비활성 가능하므로 스파이크 불필요).
- 기존 셸(사이드바, 탑바, 라우팅) 유지 + 화면별 점진 교체: 폐기(셸 포함 전면 재설계).
- "빅뱅 전면 교체 비권장" 의견: 철회(사용자가 전면 재설계로 확정).

### 구현 시 참고 (제약 아님, 실행 편의용)
- 기능/데이터 파악 소스: 기존 화면 frontend/src/screens/*, API app/*/router.py.
- MUI 폰트/아이콘: 인터넷 접근되면 CDN 사용 가능, 오프라인 대비 로컬 번들도 선택지. 번들 크기 증가는
  사내 LAN 도구라 감내 범위.

- 클로비 6종(클로버, 로봇, 블롭, 별, 구름, 새싹) 시안을 만들었으나 사용자가 6개 전부 반려. 다음 주 재논의.
  방식은 유효(코드 SVG + CSS, 워크플로 병렬 생성). 다음엔 컨셉을 먼저 좁힌 뒤 생성.
