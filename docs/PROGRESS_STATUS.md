## 2. 완료 단계 정의 (이 문서 전체에서 이 구분을 지킨다)

```
미착수 → 진행 중 → 구현완료 → 테스트완료 → 배포완료 → 실환경검증완료
```

- **구현완료** = 코드 수정 + 회귀 테스트 작성 + revert-to-verify(고치기 전으로 되돌려 테스트가
  실패하는 것 확인) 통과. **아직 실서버에 없을 수 있다.**
- **배포완료** = `UPGRADE_OK` + 서비스 3종 `active` + `/healthz`·`/readyz` 200.
- **실환경검증완료** = 배포된 실제 서버에서 그 버그의 구체적 증상이 재현 안 되는 것을(또는
  고쳐진 동작을) **직접 관찰**했다(curl/Chrome/DB 조회 등). 코드를 고쳤다는 사실만으로는
  이 라벨을 못 붙인다.

BACKLOG.md의 상태 문자열이 이 구분과 정확히 대응한다: `발견` = 미착수, `구현완료` = 구현+
테스트완료(배포 여부는 커밋/배포 이력으로 별도 확인), `실환경검증완료` = 전체 완료.

## 5. 원래 계획과의 역대조 (Master Plan vs 실제 진행)

### 5-1. 순서 이탈
`docs/WORK_PLAN_INDEX.md` §3은 **"디자인 시스템(1) → AI 도우미(2) → 관리자 IA(3) →
기능/권한 E2E(4) → 전체 재순회(5+)"** 순서를 "근본 원인이 아래로 흐르는 순서"라고 명시하며
"뒤집으면 두 번 일한다"고 경고한다. Cycle 4는 이 순서 없이 **Opus 6라운드가 남긴 CORE/UA/UB
카테고리**(성격상 §3의 4번 "기능·데이터·권한 E2E"에 가장 가깝다)로 곧장 들어갔다.

**재판단**: 이 이탈을 지금 되돌릴지는 미결정이다. CORE/UA/UB가 보안·데이터무결성 성격이라
"먼저 고쳐야 사고를 막는다"는 정당성은 있지만, 디자인 시스템(1)을 건너뛴 채 화면을 계속
고치면 Master Plan이 경고한 "뒤집으면 두 번 일한다"가 실제로 발생할 위험이 있다(예: 지금
고친 컴포넌트가 나중 디자인 시스템 재설계에서 다시 바뀜). **다음 결정 필요 — 그때까지
"보류"가 아니라 "결정 안 됨"으로 기록한다.**

### 5-2. Decisions 재검토 (규칙 때문에 누락된 것이 있는가)
`docs/DECISIONS.md`를 훑어 "하지 않는다"류 결정을 확인했다. 주요 1건:

- **D-21**(`RN-01`~`RN-03`을 실서버에서 재현하지 않는다): **여전히 유효** — 실서버에 연결된
  Notion 워크스페이스가 현대모비스·SK하이닉스 등 **실제 고객사** 데이터라서, 서버가 테스트용
  이어도 그 쓰기 부작용은 진짜다. 이건 낡은 판단이 아니라 지금도 유효한 안전 경계다.
  **단, 이 결정은 "서버 재현 방법"만 배제한다 — `RN-01`~`RN-14` 자체(로컬 스텁 재현 +
  코드 수정)는 여전히 미착수 상태이고 이 문서 §4가 그렇게 기록한다.** "규칙 때문에 안 했다"가
  "그러니까 안 해도 된다"로 슬며시 바뀐 곳은 없었다.

## 6. 이번 세션에서 "정당한 미검증"으로 남긴 것들 (핑계가 아니라 근거)

아래는 §1의 "실환경검증완료" 분모에서 뺀 항목들과 그 이유다. 매 배치 문서(WORK_STATE.md)에
개별적으로도 적혀 있다 — 여기 모은 이유는 패턴을 보기 위해서다.

| 유형 | 예시 | 왜 실서버에서 못/안 하는가 |
|---|---|---|
| 순수 프로세스 내부 상태 | ratelimit 버킷 LRU, SettingsCache 참조 공유 | HTTP로 관측 불가 — 파이썬 객체 자체를 봐야 함 |
| 운영 위험이 더 큰 재현 | DB 잠금·손상 주입, 파일 타임스탬프 조작 | 공유 프로덕션 서버에서 고의로 장애를 만드는 것 |
| 데이터 규모 재현 불가 | ratelimit 1만 버킷 도달 | 실서버에 1만 개 서로 다른 클라이언트를 만드는 건 낭비/비현실적 |
| 정리 경로가 없는 리소스 | SecretMissingError용 테스트 Integration | Integration Registry에 **삭제 API가 없다** — 만들면 영구히 남는다(비활성화만 가능) → **이번엔 만들지 않기로 결정** |
| 도구 자체의 한계 | 제어문자를 담은 curl 요청 | 셸 도구가 제어문자 포함 명령을 승인 UI에서 숨겨질 위험으로 차단 |
| 실제 고객 데이터 보호 (D-21) | RN-01~03 서버 재현 | 연결된 Notion 워크스페이스가 실제 고객사 데이터 |

**이 표에 없는 "구현완료" 항목**(예: 상당수 CORE 항목)은 **아직 이유를 안 적었거나 단순히
시도 안 한 것**이다 — "이 표에 있어야 정당하다"가 아니라 "이 표에 없으면 아직 판단 안
됐다"로 읽는다.
