## 8. 검증 한계 (정직하게)

1. **`node_modules/` 는 Audit 시작 전부터 dirty** 했다(RUN CONTEXT `pre_existing_dirty_paths`).
   사용자의 것이므로 건드리지 않았다. 이 Audit 의 어떤 결론도 그 경로에 의존하지 않는다.
2. **`/approvals` 목록의 범위를 확정하지 못했다** — 「내가 결재자인 건만」인지 「전체」인지.
   원시 API 와 화면의 결과가 달랐으나 범위 차이일 수 있어 단정하지 않았다(`FC-15` 아래 UNKNOWN).
3. **`change_password` 500 이후 부분 쓰기 잔존 여부를 확인하지 않았다.** 트랜잭션 하나이므로
   롤백이 정상이면 남지 않아야 하지만 직접 읽어 보지 않았다 — `PA-RC-0032` 수용 기준으로 넘겼다.
4. **W축은 `STATIC_ONLY`** 다. 소스 전수 스캔은 했지만 시간대·만료를 실행으로 검증하지 않았다.
5. **Coverage 2,340칸 중 1,266칸(54%)이 여전히 UNSEEN** 이다. 전부 사유가 달려 있고
   `unseen_without_reason=0` 이지만, 이것은 「제품 전체를 실행으로 훑었다」는 뜻이 **아니다.**
   수렴의 근거는 Coverage 비율이 아니라 **Blind Re-Audit 2회 연속 clean** 이다.
6. **배포를 실행하지 않았다** — Auditor 의 역할 경계다(PHASE 2 의 일). 배포 경로·설정은 읽고
   평가만 했다.
7. **제품 상태를 바꾸는 destructive action 을 하지 않았다.** 유일한 쓰기는 QA 계정 자신의
   비밀번호 재설정이며, 값은 메모리에만 두고 로그·문서·커밋 어디에도 남기지 않았다.
