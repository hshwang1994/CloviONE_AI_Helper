# 진행 중이던 작업의 완료 기록 (CURRENT_WORK_COMPLETION)

전면 제품 검수로 넘어가기 전에, 직전 세션에서 진행 중이던 작업을 먼저 끝냈다.

## 이어받은 상태

n8n 워크플로 v7(댓글 작성 기능 포함)을 사용자가 임포트하고 러너 3.11.0을 배포한 직후였다.
댓글 프로브가 빈 응답을 반환했고 실행 118번이 error로 남아 있었다. 원인은 미상이었다.

## 확인한 원인

`Notion 변경 결과` Code 노드에 이전 세션이 넣은 코드 한 줄이 문자열 안에서 줄바꿈이 되어
JavaScript 문법 오류를 냈다. n8n은 쓰기 경로(생성·변경·댓글)에서만 이 노드를 실행하므로
조회는 멀쩡하고 쓰기만 전부 죽어 있었다. 웹훅은 응답 없이 끝나 사용자에게는 빈 화면으로 보였다.

```
if (context._applied_line) { responseText += '
                                             ^  SyntaxError: Invalid or unexpected token
```

## 그 과정에서 드러난 더 큰 문제

수정본을 `workflow_entity.nodes`에 SQL로 직접 UPDATE하고 n8n을 재시작했는데도 옛 코드가 계속 실행됐다.
python으로 DB를 다시 읽으면 수정본이 보이는데, `n8n export:workflow`는 옛 코드를 내보냈고
실행 스냅샷(`execution_data.workflowData`)에도 옛 코드가 찍혀 있었다. n8n을 완전히 stop/start해도 같았다.

**raw SQL 수정은 n8n 자신의 로딩 경로를 건너뛴다.** 고친 줄 알고 40분을 태웠다.
지금부터 워크플로 수정은 n8n CLI(`import:workflow` → `update:workflow --active=true` → 재시작)로만 하고,
검증은 반드시 `n8n export:workflow`로 되읽어서 확인한다.

## 완료한 것

| 항목 | 상태 | 확인 방법 |
|---|---|---|
| 문법 오류 수정 및 워크플로 복구 | 확인함 | `n8n export:workflow`로 되읽어 깨진 코드 없음 확인, active=true |
| 티켓 생성 경로 | 확인함 | 라이브 대화 2턴으로 실제 Notion 티켓 생성됨 (링크 반환) |
| 댓글 작성 경로 | 확인함 | 라이브 대화로 실제 Notion 댓글 게시됨 (Notion API로 댓글 존재 확인) |
| 프로젝트 없는 티켓 생성 | 확인함 | "프로젝트 없음"이라고 답하면 관계 필드를 비우고 생성 |

## 그 과정에서 발견해 함께 고친 결함

라이브 프로브를 돌리자마자 검수 없이도 결함이 쏟아졌다. 전부 고치고 배포했다.

1. `is_create_intent`가 문장 앞쪽의 '생성/등록' 낱말에 강탈됐다. "티켓 생성 기능 검증 검색해줘"가
   검색이 아니라 티켓 생성으로 갔다. 한국어는 동사가 뒤에 오므로 마지막 동사가 요청의 정체다. (3.12.0)
2. `project_score`가 프로젝트 이름의 흔한 낱말(기능, 검증)에 걸려 엉뚱한 프로젝트 조건을 걸고 0건을 냈다.
   프로젝트 지목은 우연이 아니라 이름이어야 한다. 긴 연속 일치나 이름의 한 낱말만 인정한다. (3.13.0)
3. "프로젝트 목록 보여줘"가 티켓 214건을 반환했다. 프로젝트 자체를 묻는 질문에 답이 없었다. (3.13.0)
4. 담당자 이름이 해석되지 않으면 화면에 Notion 사용자 UUID가 그대로 찍혔다. (3.13.0)
5. 생성 흐름이 프로젝트를 필수로 요구했다. 작업 DB에는 프로젝트 없는 티켓이 실제로 존재한다. (3.14.0)

## 검수로 넘어간 시점

위 항목을 러너 3.14.0으로 배포하고 라이브에서 확인한 뒤, 전면 제품 검수를 시작했다.
검수 결과는 [DEFECT_AND_IMPROVEMENT_LOG.md](DEFECT_AND_IMPROVEMENT_LOG.md)에 있다.
