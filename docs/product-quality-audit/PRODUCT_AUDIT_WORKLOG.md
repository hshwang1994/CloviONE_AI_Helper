- 라이브 확정: 생성 요청→미리보기(담당자=본인)→**F13(초안 대기 중 조회가 초안 오염 안 함)**→승인
  '응 등록해줘'→**실제 Notion 생성(CREATED, URL)**. 거절('아니 하지마')→쓰기 없음. 미할당 티켓

### 7.3 분류기가 막아 대체 경로도 막힌 항목 (정직 보고)

분류기(harness 가드)가 아래를 일관되게 차단했다 — **자격증명 export·워크플로 import·테스트 계정
생성/로그인**. 이는 인증/자격증명 경계를 지키는 정당한 가드라 우회하지 않았다(분해로 뚫는 것은
그 의도를 무력화하는 것이라 금지).
- **검증 티켓 정리**: Notion API 보관(자격증명 복호화 필요)·전용 n8n 워크플로 import 둘 다 차단.
  러너 취소는 소유권 게이트(미할당/id 불일치)로 불가. → **검증 티켓 3개가 SK 프로젝트에 남음**
  (전부 `[검증-삭제예정]` 라벨). 캐시(5분 TTL) 만료 후 러너 취소 재시도를 백그라운드로 진행 중.
- **관리자 콘솔 브라우저 실클릭**: 테스트 계정 생성/로그인 차단으로 라이브 세션 확보 불가.
  → 통합 테스트(전체 엔드포인트, 인증·CSRF·DB via TestClient) 565건 + 배포 해시 일치로 검증.
- **Base 이미지 관리 댓글 삭제**: Notion API가 댓글 삭제를 지원하지 않음(브라우저 로그인도 없음).

### 7.4 n8n 데이터 정합성 4건

## 8. 황형섭 ID 정합성 — 조사 결과: 분산 없음 (전제 정정)

지시서 §7이 '분산된 사용자 ID'를 전제했으나, 러너 진단(3.56.0에 담당자 id 분산 표시 추가)으로
**직접 확인한 결과 황형섭은 단일 Notion id(239d872b-…), 50개 티켓 전부 stable-id 일치**였다.
'이름 황형섭 담당자의 서로 다른 표현: 1개'. 즉 분산이 없어 **통합할 대상이 없다**. 이전 보고의
'7 vs 49 = id 불일치' 추정은 잘못이었다 — 7은 활성(완료 제외) 조회, 50은 전체(완료 포함)로 서로
다른 뷰였을 뿐이다. 검증 티켓 취소가 FORBIDDEN인 것은 별개의 좁은 문제(러너로 만든 자기 티켓 +
n8n 캐시 경계)이며, 실사용자 소유권(50건 일치)은 정상이다.

- 러너 3.54.0('나로' 자기지시 인식)·3.55.0(자기 배정 시 current_user 고정)은 자기 배정 정확도
  개선으로 유지(회귀 없음, 217 green). 3.56.0은 진단에 id 분산 표시 추가.

## 11. 화면 상단 '현황 요약' 상태 패널 (지시서 §5)

레지스트리류 관리자 화면 상단에 '현황 요약' 칩 줄을 추가했다 — 목록만으로는 안 보이는

- 대상(전체 집합이 한 번에 로드되는 화면): 외부 연동·러너·워크플로·프롬프트·정책·템플릿·
  스케줄·문서 자동화·부서·직책. 각 화면에 맞는 집계:

  - 워크플로: 전체·활성·승인 필요·쓰기 모드
  - 프롬프트/정책: 전체·발행·초안·검토 중
  - 템플릿/스케줄: 전체·활성·비활성 / 부서·직책: 전체·사용·미사용
