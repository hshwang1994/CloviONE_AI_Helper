# 관리자 기능 검수 (ADMIN_CAPABILITY_REVIEW)

기준은 하나다. 관리자가 개발자 도움 없이 시스템을 이해하고 안전하게 운영할 수 있는가.
설정 화면이 존재한다는 사실은 근거가 되지 않는다.

## 위험했던 것 (수정 완료)

| 기능 | 무엇이 위험했나 | 조치 |
|---|---|---|
| 작업 큐 | operator가 목록 한 번으로 전 사용자의 채팅 원문, 요청자 이메일, 첨부 이미지 원본을 읽었다. 같은 내용을 대화 API로 읽으면 403인데 큐가 우회로였다. 사용자가 채팅에 붙여넣은 비밀번호나 키도 그대로 보였다 | 응답에서 원문과 첨부를 제거하고 운영 메타데이터만 남겼다. 실제 관리자 계정으로 로그인해 응답 필드 15개에 원문이 없음을 확인했다 |
| 스케줄 즉시 실행 | run-now가 활성 여부를 보지 않아, 승인 게이트를 통과하지 않은 스케줄의 쓰기 워크플로를 즉시 실행할 수 있었다 | 승인 게이트가 지키려는 것은 '이 정의로 실제 실행하는 것'이다. run-now도 같은 문을 지나게 했다 |
| 문서 생성 | 발행 승인 정책을 요청자가 고를 수 있어(mode=auto_publish) 무승인 발행이 가능했다 | 정책은 서버가 강제한다. 요청자가 고르는 값이 아니다 |
| 스케줄 승인 | 승인이 대상 id만 저장해서, 승인 대기 중 정의를 바꾸면 승인자가 본 적 없는 내용이 활성화됐다 | 승인 시점의 정의를 스냅샷으로 저장하고, 실행 시 다르면 승인을 무효화한다 |
| 비밀번호 재발급 | 확인 절차 없이 한 번의 오클릭으로 타인 계정의 비밀번호가 즉시 무효화됐다. 더 가벼운 '세션폐기'에는 확인이 있어 위험도와 확인 강도가 역전돼 있었다 | 무슨 일이 벌어지는지 설명하는 확인 절차를 붙였다 |

## 쓸 수 없던 것 (수정 완료)

| 기능 | 무엇이 문제였나 | 조치 |
|---|---|---|
| Notion 매핑 | 구조적으로 항상 비어 있었다. 매핑 행을 만드는 유일한 경로가 이미 매핑된 사용자를 아는 API뿐이라, 콘솔에는 진입점이 없고 5개 행 액션이 전부 도달 불가였다. 문서에 적힌 절차가 실행 불가였다 | 모든 직원을 목록에 보여주고(연결 안 된 사람은 unmapped) 거기서 연결하게 했다. 이 기능이 무엇이고 왜 선택 사항인지 화면에 설명을 붙였다 |
| 감사 로그와 승인 | 행위자와 요청자가 사람 이름 대신 UUID로 표시됐다. 승인자는 자기 요청인지도 화면에서 판별할 수 없었다 | 사람 이름과 이메일로 해석해 보여준다 |
| 설정 버전 이력 | API에는 이력과 롤백이 있는데 콘솔에 UI가 없어, 잘못 저장한 설정을 되돌릴 방법이 화면에 없었다 | 이력과 롤백 진입점을 콘솔에 붙였다 |
| 진단 번들·백업 안내 | 구현·권한·마스킹까지 끝났는데 진입점이 없어 URL을 직접 쳐야 썼다 | 콘솔에 진입점을 붙였다 |
| 테이블 정렬 | 현재 페이지 20건만 정렬하면서 전체(예: 137건)를 정렬한 것처럼 보였다. 관리자가 '가장 오래된 실패 작업'을 찾으면 틀린 답을 얻는다 | 서버 정렬을 쓰거나, 이 페이지 안에서만 정렬됨을 화면에 밝힌다 |

## 접근성 (수정 완료)

모달에 Escape 닫기, 열릴 때 포커스 이동, 포커스 트랩이 없어 키보드 사용자가 갇혔다.
폼 레이블이 입력과 연결돼 있지 않아 스크린리더가 읽지 못했고, 체크박스는 레이블 클릭도 안 됐다.
정렬 가능한 헤더는 키보드로 도달할 수 없었고 정렬 상태가 스크린리더에 노출되지 않았다.
전부 고쳤다.

## 구현됐지만 실제 트래픽과 무관한 것 (기록만)

기능 지도 작성 중 확인한 것이다. 지금 당장 해가 되지는 않지만, 관리자가 이 화면을 보고
'설정하면 동작한다'고 믿을 수 있어 기록해 둔다.

- 러너 레지스트리의 등록·활성화·서킷 브레이커가 실제 채팅 트래픽 경로에서 호출되지 않는다.
  채팅은 n8n 웹훅을 직접 부르고, 레지스트리는 '테스트' 버튼에서만 쓰인다.
- Prompt/Policy의 발행된 내용을 실제로 소비하는 코드가 없다.
- AutomationTemplate(target_type=runner)의 실행 경로가 없다.
- 일반 사용자용 알림 UI가 채팅 화면에 없다(API는 있다).

이것들은 '이름만 있고 동작하지 않는 기능'에 해당한다. 다만 제거할지 연결할지는 제품 방향의
결정이라 임의로 지우지 않았다. 사용자 판단이 필요하다.
