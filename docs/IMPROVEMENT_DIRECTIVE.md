# AI 업무 관리 시스템 전반 개선 지시서 (사용자 원문 요약, 2026-07-15)

> 사용자가 제시한 상시 작업 기준. **여러 세션에 걸친 프로그램**이며, 각 세션은 이 문서와
> BUILD_LOG의 진행 상황을 읽고 이어간다. 예시는 방향 설명용이지 범위의 경계가 아니다.

## 핵심 원칙
1. 문장을 조건문으로 옮기지 말고 **의도(작업유형·대상·관계·조건·후속행동)를 구조화**해 처리한다.
2. 같은 원인이 미치는 **다른 화면·API·데이터 흐름까지 함께** 고친다.
3. **설계에서 멈추지 않는다** — 구현·테스트·검증 반복까지가 한 단위.
4. 실제 데이터·현재 사용자·권한 기준으로만 답한다. 추측 금지, 없으면 없다고.
5. 파괴적 작업(삭제·대량변경)은 권한 확인·영향 표시·확인 절차·사후 재조회.
6. 하드코딩 금지(문장·사용자·프로젝트·색상), 결과 0/1/수백 건·권한 없음·데이터 누락 케이스 처리.

## 작업 축 (요약)
- **조회**: 관계(담당/생성/요청/참여)·프로젝트·상태·기간·우선순위·검색어·정렬·그룹화·조합을
  구조화된 질의로. (현 데이터 모델 한계: Notion 작업 DB에 '요청자/참여자' 필드 없음 — 가능한 축부터)
- **생성**: 대화 기반, 기존 컨텍스트·기본값 활용, 필수값만 되묻기, 임의 사실 저장 금지.
- **변경**: 제목/본문/담당/상태/우선순위/날짜/프로젝트/일괄, "두 번째 티켓" 등 맥락 참조 정확성.
- **삭제/취소**: 안전 절차(권한·영향·복구·확인·사후조회). 미지원이면 정직하게 안내.
- **프로젝트**: 목록·현황·담당·티켓 수·진행률 조회.
- **후속 작업**: 이전 결과 기반 필터/정렬/상세/변경 연결, 주제 전환 시 조건 미승계.
- **결과 표시**: 목록=핵심 정보(제목·프로젝트 배지·상태·담당·마감), 상세=전체. 본문 요약은
  원문 기반(현재 본문 미수집 — blocks 수집 필요 여부 검토), 프로젝트 시각 구분(색+이름).
- **새 대화 추천**: 실제 구현된 기능 기준, 조회 편중 금지(생성·변경·요약 포함), 권한 반영.
- **정확도**: 조회→검증→표시 순서, 수치 대조, 상대 날짜 일관 기준(Asia/Seoul), 실행 후 재조회.
- **오류 처리**: 내부 메시지 노출 금지, 실패 원인+다음 행동 안내.

## 완료 기준 (발췌)
- 어떤 표현이든 의도 이해 / 조회·생성·변경 흐름 자연 연결 / 실데이터와 불일치 없음 /
  권한·프로젝트 범위 정확 / 공통 구조 개선(개별 예외 수리 아님) / 테스트 실행 완료 / 회귀 없음.

## 보고 형식
원인→구조 변경→축별 개선→수정 파일→실행한 테스트와 결과→미확인 범위→제외 항목과 이유.
